### What changed

- **`src/lib/plan-guard.ts` (new, pure).** `buildDayGuard` answers "has this
  plan row already been trained": its date is before today, it has logged
  sets, or the person closed it (missed, rested, swapped for an activity). A
  moved session is judged on the day it moved to, through the existing
  `sessionForDate`, used as it is. `planDaysInWindow` turns "N days from
  today" into the plan rows trained on those dates.
- **`src/lib/effective-constraints.ts` (new, pure).** The profile's injuries
  plus every active time-boxed injury adaptation, and the kit an active kit
  change puts the person on. `constraintProfile` is the clone a pool is built
  from; it is never saved.
- **`src/lib/plan-edit-context.ts` (new, I/O).** Loads both. If it cannot
  read what was logged today it treats today as trained and logs why; it
  never changes something on the strength of "could not check".
- **A REQUIRED context on every function that replaces days**:
  `substituteForInjury`, `substituteForEquipment`, `rebuildForInjury`,
  `rebuildAgainstProfile`, `rebuildForWeightBasis`, `rebuildFromCurrentWeek`,
  `reconcileToStatedCeilings`, the weight-basis offer, the three adaptation
  executors and the six rebuild executors. Required on purpose: the compiler
  listed every call site, and a new one cannot leave it out.
- **The day guard is in two places only**: where slots are substituted, and
  the splice in `rebuildAgainstProfile`, which is now per day. So every
  existing rebuild offer (equipment, style, goal, days, session length, second
  sport, weight basis, stated ceilings) stopped rewriting the trained days of
  the current week as a side effect.
- **Adaptations address days by date.** The coach's two cards, the exercise
  row's two appliers and the three executors all call `planDaysInWindow`.
  The card names rows by date ("Thursday 15 Oct") in date order and says
  "Covers Thu 8 Oct – Wed 21 Oct".
- **The shared settle pass now runs after an adaptation** (warm-up rebuilt,
  set hierarchy, one weight per lift), confined to the days it changed.
- **`plan_adaptations.pre_image` holds the changed days and slots**, not whole
  weeks (a JSON column, so no migration). `revertAdaptationChanges` reads both
  shapes. For a row written before today there is no list of what was
  changed, so it puts back only exercises the adaptation would itself have
  removed, never one the person has since banned.
- **Ending.** A day nobody touched since goes back exactly as it was. On a day
  the person edited, each slot is put back only if it still holds what the
  adaptation put there. A trained day is never touched. `endAdaptationEarly`
  had no caller; it now has three: the Profile line, the Exercise-tab line,
  and the coach's "recovered" card when the area named is being eased off
  temporarily. So "tell me anytime to end it early" is true.
- **Pools.** App builds one `poolProfile` and hands it to the Exercise tab
  (swap list, add-an-exercise, session rebuild, warm-up), to a ban's
  replacement and to the coach (add, session rebuild, ban). Profile WRITES
  still use the saved profile; a gate holds that.
- **The coach's context line** now reads, during a knee adaptation:
  *"Currently working around: Shoulders — the plan already avoids exercises
  that load this. Temporarily easing off: Knees (until 22 Oct) — those days of
  the plan are already adjusted, and it ends on that date or as soon as they
  say it has cleared."* Built in the browser, so no deploy.
- **The travel card (H17)** goes through the same guarded path: it respects
  the active adaptation, keeps the movement pattern, and states the dates it
  covers. **When "next week" starts was NOT changed** (still today); that
  question is open.
- **The load path in App.** The expiry sweep used to run beside the block
  checks, two writers of the same weeks from one snapshot. It now runs first
  and the block checks wait for it.

### Decided as a CSCS coach, with the basis

- **An automatic substitute stays on the same movement pattern and the
  person's own style whenever one exists.** Basis: a substitute chosen FOR
  someone should meet the bar an exercise generated for them meets. The
  18 Sep widening (show off-style options, loaded ones first) was a ruling
  about what a person is SHOWN and chooses from. Off-style only when the style
  has nothing for that movement, and the row says so.
- **An isolation slot is never filled from unrelated work; it is left out and
  the row says so.** Basis: a third squat in place of a triceps kickback
  trains nothing the slot was for and adds knee-dominant volume the week did
  not programme, on a knee the person has just reported. A compound slot
  keeps Ashley's 30 Aug ruling ("swap in different work"), and the row carries
  the reason.
- **A substitute already used this week is avoided when another fits, and
  taken rather than dropping the slot when it is the only one.** Basis:
  repeating one stand-in on every leg day narrows the stimulus the adaptation
  was meant to preserve; a hole is worse than a repeat.
- **During an active injury adaptation, a rebuild generates the weeks it
  reaches against the profile WITH that area flagged, whole weeks.** The days
  of its last week that fall after it ends stay cautious a few days longer
  than asked. Basis: generation balances a week as a unit, and the error is on
  the safe side.

The five questions:
1. **Training effect.** The adaptation covers the days it claims; trained days
   stay as trained; substitutes are on-pattern and on-style.
2. **What it takes away.** Isolation slots that used to be cross-filled are
   now left out (and, as before, any dropped slot makes the injury card offer
   a rebuild of those days instead of a patch). One substitute no longer lands
   on every leg day. Not counted on the grid; see "not verified".
3. **Fundamentals.** The settle pass restores the warm-up, set hierarchy and
   weight coherence adaptations skipped.
4. **Floors and ceilings.** `assessAdaptation`'s meaning is unchanged: I first
   made dropped isolation slots not count toward "rebuild instead", and
   `test:injury-rebuild` caught it (a shoulder injury on a full gym stopped
   being rebuilt and would have left 64 holes). Put back. The 15% ratio still
   divides by the whole programme; with a date-true window the numerator is a
   little smaller. It was not re-measured.
5. **Scope.** No change to what counts as a red flag; no medical judgement.
