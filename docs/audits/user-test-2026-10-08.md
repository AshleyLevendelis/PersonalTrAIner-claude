# User test, 8 Oct 2026: a day-to-day click-through on the real screens

**What this is.** I tapped through the app the way a person does every day, on the real screens at phone size (390x844). I did not change any app code. Each finding below says how bad it is, how to make it happen again, what I expected, what I saw, the screenshot, and whether the problem is in the **app** or only in the test setup (the **harness**).

**The code tested.** Commit `3ad3325d` (`claude/coach-empty-text-fix-2c4bzv`, 8 Oct 05:02). This worktree started on an older commit (`0df0bc12`, 30 Sep). I moved it to the newest working-branch commit so the test covers the week-boundary work.

**How.** `.tour-harness/explore/serve.mjs` keeps one headless Chromium running (port 9601) over the built harness. `do.mjs` sends it one tap, typed value, screenshot or page read at a time. To reproduce:

1. Build: `npx vite build --config .tour-harness/vite.config.ts`
2. Start the host: `node .tour-harness/explore/serve.mjs` (static site on 8761, controls on 8762)
3. Open a page: `node .tour-harness/explore/do.mjs nav '/.tour-harness/real.html?tour=off#/tab/exercise'`

The fake database is in memory, so **every page load starts from the fixture again**. To get a clean start, clear localStorage first: `do.mjs js "localStorage.clear()"`. Paths below are relative to `http://127.0.0.1:8761`. The harness "today" is Wed 16 Sep 2026.

**Severity scale:** **blocks use** · **wrong number or data** · **confusing** · **cosmetic**.
Screenshots are in `docs/audits/user-test-2026-10-08/`.

## Harness-only, or not reachable here

- **Swap and ban an exercise.** In the harness these are dead (`onSwapExercise` and `onBanExercise` are no-ops in `real.tsx`), so they are untested here. App.tsx wires them.
- **Swapping or regenerating TODAY's meal** from the swap list (`onSwapMealSlot` and the regenerate handlers are no-ops in `real.tsx`). Upcoming-day swaps go through the app's own hook and were tested.
- **Monday shows "missed" despite a logged squat.** The fixture's set log has no session attached, and the strip reads logs through sessions. Real logs always have one. The same fixture row makes Home's tips count Monday as a session: Tools shows "0 sessions · 1 PR".
- **Chat timestamps** ("Thu, 8 Oct, 5:47 AM") use the real clock while the app's day is pinned to 16 Sep. This mismatch exists only in the harness.
- **The round timer is not visible off the Tools tab**, because `real.html` does not mount the session dock.
- **The profile rebuild offer** is the harness's own stand-in, not App.tsx's dialog. That the offer was raised is proven; how it looks in the app is not.
- **Grocery Undo after a few seconds** failed once and passed twice on retry, so it is inconclusive and not reported.
- **Needs the real database or the real coach:** persistence across real days (every harness load resets the fake database); whether the coach's own words are good; meal generation and top-up against the real meal writer; phone notifications; anything in the edge functions; real PostgREST error paths; App.tsx-only gating (first-build gate, the real rebuild dialog, the onboarding insert).
